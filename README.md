# 07-routing-nextjs

  - Cтворено репозиторій `07-routing-nextjs`.
  - При здачі роботи надаються два посилання: на вихідні файли (репозиторій) та на робочу сторінку завдання, розгорнуту на [Vercel](https://vercel.com/).
  - Проєкт створено за допомогою Next.js (App Router).
  - Усі компоненти, які не прив'язані безпосередньо до маршруту та їх частин, зберігаються в папці `components`, кожен - у власній папці з такою ж назвою як і компонет, та з файлами:

    1. файл компонента з розширенням `.tsx` (наприклад, `Header.tsx`);
    2. файл стилів з такою самою назвою, що й компонент, з розширенням `.module.css` (наприклад, `Header.module.css`).

  - Загальні типи та інтерфейси винесені до файлу `types/note.ts`.
  - Функції роботи з API винесені в `lib/api/` у вигляді окремих модулів.
  - Для HTTP-запитів використовується бібліотека `axios`.
  - Стан запитів у CSR-компонентах керується через `TanStack Query` (React Query).
  - Усі компоненти типізовані з використанням `TypeScript`.
  - Код має бути відформатований за допомогою `Prettier`.
  - Стилізація - за допомогою CSS Modules.
  - У проєкті реалізована підтримка SSR та CSR, відповідно до завдання.

## Паралельні маршрути для фільтрації нотаток за тегом

У цій частині завдання потрібно реалізувати фільтрацію нотаток за тегами за допомогою паралельних та catch-all маршрутів у `Next.js`.

### 1. Створення Sidebar для фільтрації

Створіть новий файл `default.tsx` з компонентом `SidebarNotes` за шляхом `app\\notes\\filter\\@sidebar`. У цьому компоненті потрібно створити меню з посиланнями для фільтрації нотаток за різними тегами. Кожне посилання має вести на маршрут, де відображаються лише нотатки, що відповідають обраному тегу. Компонент має створити наступну розмітку:
```
<ul className={css.menuList}>
  {/* список тегів */}
  <li className={css.menuItem}>
    <a href={`/notes/filter/all`} className={css.menuLink}>
      All notes
    </a>
  </li>
  <li className={css.menuItem}>
    <a href={`url до сторінки за відповідним тегом`} className={css.menuLink}>
      Назва тегу
    </a>
  </li>
</ul>
```
На бекенді немає маршруту для отримання списку тегів, тому для роботи використайте цей перелік безпосередньо в коді.
```
const tags = ['Todo', 'Work', 'Personal', 'Meeting', 'Shopping'];
```
Кожне посилання має вести на відповідний маршрут, що фільтрує нотатки за тегом, з форматом `/notes/filter/{tag}`. Наприклад, для тега "Work" це буде `/notes/filter/Work`.
```
! Посилання All notes залишається статичне, а інші потрібно додавати динамічно за допомогою map
```

### 2. Layout для сторінки фільтрації

Усі сторінки вашого додатка повинні мати спільний хедер і футер.

Створіть окремий `layout.tsx` для маршруту `/notes/filter`, в ньому потрібно отримати sidebar в пропсах та повинна створюватися наступна розмітка:
```
<section className={css.container}>
  <aside className={css.sidebar}>{sidebar}</aside>
  <div className={css.notesWrapper}>{children}</div>
</section>
```

### 3. Оновлення структури маршрутів

Оскільки маршрут `/notes` більше нам не потрібен і замість нього буде застосовуватись динамічний маршрут з фільтром за тегом, то створіть новий маршрут `app/notes/filter/[...slug]/` та перенесіть в нього усі файли, які його обробляли: (`page.tsx`, `Notes.client.tsx`, `error.tsx` та файл стилів).

### 4. Оновлення навігації

В компоненті `Header` важливо оновити значення атрибута `href` для посилання на сторінку нотаток, тепер замість `/notes` потрібно використовувати `/notes/filter/all`.

### 5. Отримання відфільтрованих нотаток

Обов'язково ознайомся з документацією бекенда:
```
https://notehub-public.goit.study/api/docs
```
Щоб отримати відфільтровані нотатки, вам потрібно передати тег у параметрах запиту. Якщо тег не передати - сервер поверне всі нотатки без фільтрації.
```
! Важливо: бекенд не очікує тег all. Якщо вибрано фільтр All notes, тег у запиті передавати не потрібно взагалі.
```
У файлі `lib\\api.ts` потрібно оновити функцію `fetchNotes` окрім сторінки та рядка пошуку вона повинна приймати ще `tag` який також потрібно передавати у params.

### 6. Оновлення сторінки з нотатками

Тепер оновіть файли `page.tsx` та `Notes.client.tsx` які знаходяться в директорії `app/notes/filter/[...slug]/`. У серверному компоненті використовуйте `params`, в який Next.js в `catch-all` маршруті автоматично передає значення параметра як масив `slug`. На основі значення `slug` отримайте поточний тег фільтрації та використайте його під час виконання prefetch, та передайте пропсом в клієнтський компонент `NotesClient`.

У клієнтському компоненті `NotesClient` потрібно отримати пропс tag та використати його в `useQuery`.

### 7. Очікувана поведінка

Така фільтрація дозволить користувачу швидко перемикатися між нотатками, що мають певний тег, і зручно фільтрувати їх, не перезавантажуючи всю сторінку. Реалізація через паралельні маршрути, дозволяє змінювати лише ту частину сторінки, яка відповідає за відображення нотаток.


Наприклад, при натисканні на тег "Work" URL має змінюватись на `/notes/filter/Work`, але сама сторінка не має перезавантажуватись — лише відбудеться зміна контенту в області відображення нотаток.


## Модальне вікно з деталями нотатки

У цій частині завдання потрібно реалізувати попередній перегляд нотатки в модальному вікні `Modal` за допомогою перехоплення маршрутів (Intercepting Routes) у `Next.js`.


### 1. Створення паралельного маршруту

Створіть паралельний маршрут `app\\@modal`. У цій директорії обов'язково створіть файл `default.tsx` який повинен повертати `null`


### 2. Підключення modal у RootLayout

Додайте слот `modal` у компонент `RootLayout` поряд із `children`.


### 3. Реалізація перехоплення маршруту

У папці `app/@modal` реалізуйте interception route для маршруту `notes/[id]`. Тут слід згадати синтаксис для побудови перехоплювача


### 4. Серверний компонент NotePreview

У перехопленому маршруті створіть серверний компонент `NotePreview`, у якому заздалегідь виконується prefetch з гідратацією кеша.


### 5. Клієнтський компонент NotePreviewClient

Також створіть клієнтський компонент `NotePreviewClient` в файлі `NotePreview.client.tsx`. Реалізуйте в ньому функціонал та розмітку картки, аналогічні сторінці деталей нотатки, за виключенням того, що вся розмітка повинна бути обгорнута компонентом `Modal` (цей компонент у вас повинен бути з минулих ДЗ)


### 6. Очікувана поведінка

При переході на маршрут типу `/notes/{id}` повинно відкриватися модальне вікно з деталями обраної нотатки. Основна сторінка зі списком нотаток при цьому має залишатися на фоні та не перезавантажуватись.


Закриття модального вікна відбувається при поверненні на маршрут сторінки, з якої відкривалось модальне вікно (наприклад, `/notes/filter/Work`, `/notes/filter/all` тощо)
